Welcome to CloudDock

CloudDock is being developed as a unified hosting platform for game servers, Discord bots, websites, virtual private servers, and databases. The goal is to make hosting easier to understand and manage from one workspace.

Launch policy: free until further notice

All planned hosting services are intended to be free during the initial launch period. Free does not mean unlimited: resource and fair-use limits will be documented before services open.

Choose the right product

Start with the software you need to run. Consider supported versions, runtime requirements, memory, storage, network traffic, backups, and whether you need root-level control.

  • Choose game hosting for multiplayer server software.
  • Choose application hosting for bots and long-running processes.
  • Choose website hosting for static sites and web apps.
  • Choose VPS hosting when you need a general-purpose virtual machine.
  • Choose database hosting for a managed data service.

Game server preparation

Before deploying a game server, identify the game and server version, required ports, expected player count, plugins or mods, and memory requirements. Keep a separate copy of important world and configuration files.

Bots and application preparation

Know the language runtime and version your app needs. Keep dependencies documented and store secrets in a protected environment-variable manager when one is available. Never commit bot tokens or API credentials to source control.

Website preparation

Confirm whether your project is static or requires a server-side runtime. Prepare a production build, configure routes and asset paths, and plan how you will manage your domain and HTTPS. GitHub Pages itself serves static files; it does not run backend processes.

VPS preparation

List the operating system, CPU, memory, storage, network, and administrative access your workload requires. Plan patching, firewall rules, backups, and recovery before exposing a service to the internet.

Database preparation

Choose a database engine based on application requirements. Plan access roles, backup frequency, restore testing, connection security, and data retention. Never expose administrative database credentials in frontend code.

Before you deploy

  • Confirm software versions and licensing requirements.
  • Estimate resource needs realistically.
  • Keep backups of important project data.
  • Document ports, domains, and dependencies.
  • Review acceptable-use and service terms before deployment.

Security basics

Use unique passwords and multi-factor authentication when available. Never share passwords, API keys, access tokens, or recovery codes. Use least-privilege access and rotate credentials if they are exposed. Support staff should not need your password to troubleshoot an issue.

Frequently asked questions

Can I order hosting today?

Not yet. CloudDock is in development and this website is a preview. The free policy does not mean services are currently provisioned.

Will there be paid plans?

All planned services are free until further notice. Any future policy change will be communicated before paid options are introduced.

Does GitHub Pages run my servers?

No. GitHub Pages serves the static frontend. Hosting workloads require separate backend APIs and compute infrastructure.

Where can I follow development?

Visit the CloudDock GitHub repository and the public roadmap.
